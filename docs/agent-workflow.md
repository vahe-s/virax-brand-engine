# Agent workflow

## Read and resume

1. Read START-HERE.md and AGENTS.md.
2. Read the current private profile and its version.
3. Inspect approved files and their review records.
4. Read the current task and the latest owner correction.
5. Check the available execution, vector, browser, and research tools.

Use the owner's current instructions within the tools' permission rules.
Do not import another business's profile or approval.

## Save the interview

Use the commands in docs/commands.md when shell access exists.
Use authorized private project files when shell access does not exist.
Save the same answers, versions, and review records in either path.
Explain the storage location after you save a rule.
Do not call file-only setup a server installation.

The `next` command returns up to three unanswered questions.
Treat those questions as a guide.
Use judgment when an answer makes a later question unnecessary.
Record the reason when you skip a question.

## Design seven directions

Read the business brief and its required uses.
Read docs/design-logic.md.
Ask about the icon subject and optional references.
Explain the product connection and customer reason before artwork.
Save the design plan with the `plan` command.
The engine rejects artwork commands without this plan.
Use catalog/styles.json as a point of departure.
Choose distinct structures, type treatments, palettes, and relevant applications.
Explain why each direction fits the business.
Do not claim that a business name on a catalog board makes the artwork custom.

Use native SVG geometry for symbols and construction guides.
Store custom geometry inside each concept in the design plan.
For designs outside that input, save separate SVG sources in the private task folder.
Keep those files in an explicit review manifest.
Do not call an untracked custom file part of a CLI approval.

## Create and review one sample

1. Create the selected symbol and name treatment.
2. Save the construction method and symmetry type.
3. Prepare clean, black, white, and guided versions.
4. Show actual fonts and all required glyphs.
5. Check the palette on actual backgrounds.
6. Inspect the smallest required symbol size.
7. Inspect the review board at full size and 390 px.
8. Return the sample and its exact version in chat.
9. Record the owner's approval for those files.

The CLI records a SHA-256 hash for the sample files.
A hash is a value that changes when the file bytes change.
The approval command rejects a different hash or modified sample file.
It cannot establish that the owner actually approved the design.
The agent must record the actual conversation as the approval basis.

## Finish the kit

Export the kit only after sample approval.
Follow docs/brand-kit.md for each requested file.
Keep production checks and final kit approval separate from sample approval.
Create a private final manifest with hashes for every delivered file.
Do not set checks to complete without direct evidence.

The CLI kit starts with pending production checks.
It does not claim that editable text is an outlined wordmark.
Complete outline, raster, PDF, and print work with suitable tools when the brief requires them.

## Brand changes

Read the current version before every change.
Save lasting preferences in the profile.
Keep temporary instructions in the current task.
A change to answers or style clears the sample approval.
Create a new sample after a design change.
Retain earlier profile versions and approved files as history.
